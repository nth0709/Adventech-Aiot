# Adventech AIoT: 5축 로봇팔 레이저 선 추적

팔 끝에 카메라와 레이저를 함께 달았습니다(eye-in-hand). 레이저 점이 종이 위 검정 선을
**파란 점(출발)에서 빨간 점(도착)까지** 따라갑니다. Jetson에서 실행합니다.

## 과제와 결과

| 과제 | 기록 | 결과 |
|---|---|---|
| 직선 추적 | `laser_tracker/runs/follow_run7.*` | 파란 점에서 빨간 점까지 따라감. 단, 레이저 픽셀을 고정값으로 쓰던 버전이라 실제 레이저가 선에서 약 30px 벗어나 있었음 |
| Z자 추적 | `laser_tracker/runs/z_run11.*` | 9.8초 주행, 20Hz, 중간 정지 0회. 레이저-선 거리 중앙값 5.8px / 90% 16px / 최대 23px(꼭짓점) |
| S자 추적 | `laser_tracker/runs/s_run5.*`, `s_run7.*` | s_run5: 7.9초, 중앙값 6.3px / 90% 14px / 최대 21px. s_run7(도착 판정 수정 후): 7.1초, 7.9 / 20 / 29px. 모두 20Hz, 중간 정지 0회 |

각 기록은 녹화 영상(`.avi`)과 프레임별 로그(`.csv`)로 되어 있습니다.

## 동작 방식 (`laser_tracker/follow5.py`)
- **폐루프**: 매 프레임 지금 보이는 것만 씁니다. 레이저 점, 검정 선, 파란 점과 빨간 점이 대상입니다. 예측하거나 기억해 둔 위치로는 움직이지 않습니다. 쓸 수 있는 게 안 보이면 멈추고, 1초가 지나면 중단합니다.
- **캘리브레이션**: 관측 자세 주변의 격자 자세(베이스 7 × 상하 5)에서 이미지 자코비안을 한 번 측정해 `calib_grid.json`에 저장하고, 이후 실행은 이 값을 그대로 씁니다. 관측 자세나 레이저 픽셀이 바뀌면 다시 측정하며, `--recalibrate`로 직접 다시 측정할 수도 있습니다.
- **선 검출**: 검정 선을 black-hat으로 찾고, 진한 선과 이어진 연한 픽셀만 임계의 절반까지 인정합니다(이력 임계). 용지를 비스듬히 볼 때 가로로 지나가는 구간(S자 봉우리)이 얇아져도 끊기지 않습니다.
- **레이저 확인**: 팔을 살짝 돌렸을 때 화면 이동량의 30%(최소 8px) 이하로 움직인 빨간 점만 레이저로 인정합니다.
- **도착 판정**: 레이저 밑에서 선이 끝나고, 빨간 점을 1.2초 안에 100px 이내에서 실제로 봤으면 도착으로 판정합니다(`RED_NEAR_PX`, `RED_NEAR_S`). 먼 용지에서는 빨간 점이 작아 마지막 몇 px에서 레이저 빛에 가려지기 때문입니다.
- **경로**: 현재 프레임에서 선을 따라 거리를 잽니다(geodesic). 그래서 Z자의 예각 꼭짓점도 따라갑니다. 진행 방향은 최근 진행 방향으로 정하고, 꼭짓점에서는 속도를 40%로 줄입니다.

## 아크광 시뮬레이션 (진행 중)
목표는 용접 아크광 비슷한 화면에서도 선 추적이 되게 만드는 것입니다.

- `laser_tracker/arc_filter.py`: 카메라 프레임에 아크광을 합성하는 `ArcSim`입니다.
  - 아크는 레이저 점(=토치 위치)에 놓입니다.
  - 효과 8가지를 각각 0~1로 조절합니다: `intensity`, `radius`, `glow`, `flicker`, `spatter`, `smoke`, `darken`, `streaks`.
  - 프리셋은 `off` / `weak` / `medium` / `strong`입니다.
  - 한 프레임에 약 24ms 걸립니다(Jetson, 960×600, OpenCV uint8 연산).
- `laser_tracker/arc_live.py`: 원본과 필터 화면을 나란히 띄우는 실시간 뷰어입니다. 팔은 움직이지 않습니다.
  ```bash
  python3 arc_live.py --observe     # 팔을 관측 자세로 옮긴 뒤 표시, q로 끄면 쉬는 자세로 돌아가 토크 OFF
  ```
  - 키: `0`~`3` 프리셋, `l` 필터 화면에 선 검출 결과 표시, `s` 스냅샷, `q` 종료. 슬라이더로 효과를 하나씩 조절합니다.

### 아크광 상태에서 추적 (`--arc weak|medium|strong`)
```bash
./run.sh run.out --arc weak --record out.avi --log out.csv
```
실제 용접처럼 아크는 출발점(파란 점)에서 켜고 도착점(빨간 점)에서 끕니다. 출발점까지 가는 동안은 아크가 없습니다. 아크가 켜진 동안 추적기는 필터를 거친 화면만 봅니다(`laser_tracker/arc_mode.py`).
- **토치 위치**: 필터 화면에서 매 프레임 찾은 포화 중심부(줄기 제거)입니다. 화면이 통째로 포화된 프레임은 버리고 정지합니다.
- **선 검출**: 토치 주변 반경 200px 창 안에서만 찾습니다. 조명을 평탄화하고(`line_detect.FLAT`), 포화 테두리와 플레어 줄기 주변은 제외합니다.
- **가려진 구간**: 아크 주변에서 서로 반대 방향에 있는 두 선 조각의 안쪽 끝을 직선으로 잇습니다.
- **도착 판정**: 빨간 점 인정 반경을 가려진 반경만큼 넓힙니다.

| 기록 | 결과 |
|---|---|
| `runs/arc_line_run2.*` (직선, weak) | 성공. 11.4초, 9Hz, 중간 정지 0회. 레이저-선 거리 중앙값 3.5px / 90% 45px / 최대 58px |
| (직선, medium) | 실패. 아크 바깥으로 보이는 선이 짧고 흐리며, 플레어 줄기 사이 틈이 선으로 오검출됨 |

### 다음 할 일
1. 플레어 줄기 오검출을 줄여서 가끔 45px 넘게 튀는 것을 없앱니다.
2. 아크 모드의 처리 속도를 올립니다(9Hz → 20Hz 목표).
3. medium 세기에 도전합니다. 보이는 선이 짧으니, 직전 프레임에서 본 진행 방향을 짧게만 이어 쓰는 방법을 검토합니다.
4. 레이저 픽셀이 실행 사이에 약 115px 바뀐 적이 있습니다. 레이저·카메라 장착이 단단히 고정됐는지 확인합니다(바뀌면 캘리브레이션을 자동으로 다시 측정합니다).

## 실행
```bash
cd laser_tracker
python3 follow5.py --save-rest   # 쉬는 자세 저장 (토크 off, 읽기만)
python3 follow5.py --teach       # 카메라가 종이를 보는 관측 자세 저장
./run.sh run.out --record out.avi   # 추적 (서보 포트가 안 열리면 자동 재시도)
```
- `track5.py`는 `~/so101_arm/servo_bus.py`를 불러옵니다. 저장소의 `so101_arm/` 폴더를 홈 디렉터리에 두거나(`~/so101_arm`), `track5.py`의 `sys.path` 줄을 고쳐 주세요.
- 필요 패키지: `opencv-python`, `numpy`, `pyserial`
- `laser_tracker/README.md`는 초기 3축(Arduino) 버전 문서입니다.
